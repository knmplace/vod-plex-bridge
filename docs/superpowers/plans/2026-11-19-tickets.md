# Tickets (encrypted support reports) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Maintenance > Tickets tab that collects a scrubbed troubleshooting bundle, lets the user review it and add a note, then sends it encrypted to a private Gitea repo and returns a ticket number VPB-n.

**Architecture:** Server-side pipeline `collect -> scrub -> hold by collect_id -> (user adds note) -> gzip -> RSA-OAEP/AES-GCM seal -> Gitea issue`. The preview shown is the exact server-held text that gets sealed (Submit sends only `collect_id` + note, never client text). Tickets are mirrored in a local `tickets` table for the right-hand list.

**Tech Stack:** FastAPI, aiosqlite, httpx, `cryptography` (already in requirements), pytest, single-file Jinja `index.html`.

**Spec:** `docs/superpowers/specs/2026-11-19-tickets-design.md`

## Global Constraints

- Blob format = KNM v1: `base64(JSON {"v":1,"k","n","d"})`; `k` = AES-256 key locked with RSA-OAEP (SHA-256, MGF1-SHA-256); `n` = 12-byte GCM nonce; `d` = ciphertext + 16-byte tag; all inner fields base64. Plaintext is gzip of UTF-8 text, so the decrypt tool gunzips when the bytes start with `\x1f\x8b`.
- Gitea repo `Kyle/plex_bridge_tickets` (private); bot `vpb-ticket-bot`, token scope write:issue only. Ticket number shown as `VPB-<issue number>`; first real ticket is VPB-2 (#1 was a setup test).
- Gitea base URL used by the app: `https://gitea.nikodamas.org` (users are remote; the LAN address is unreachable for them). Env overrides `TICKET_GITEA_URL`, `TICKET_GITEA_TOKEN`, `TICKET_PUBKEY_PEM` exist only for tests.
- Private key, bot password and token files stay in `b:\Claude_Apps\plex-bridge-tickets-secrets\`, never in the repo. The public key PEM and the bot token ARE committed (user decision: public-repo exposure accepted; protected by size cap + rate limit).
- Nothing leaves the box except on Submit. No provider calls anywhere in collection (bridge DB, in-memory logs, Plex API, Dispatcharr API only).
- Never push without asking; commits have no IPs/keys/provider names, no Co-Authored-By. `index.html` is Jinja: no literal `{{ }}` in JS; validate with `node --check`. New panels use `togglePanel` collapsible headers (`panel-header collapsible`).
- Size caps: bundle text <= 1.5 MB before gzip; one Gitea issue body <= 60,000 chars, overflow goes as ordered comments; one send per 60 s.
- Version bump to `0.47.0` in `app/main.py:29`.

## Review Focus

- A known secret appears inside JSON-escaped text, URL-encoded (`%2F`), or split across a log line: still replaced.
- The note box contains a secret or IP: scrubbed with the same scrubber before sealing.
- Plex or Dispatcharr unreachable / slow: that section says "unavailable: <reason>" within a 10 s timeout and the bundle still builds.
- Gitea down or token revoked: ticket saved as `unsent` with its blob, user sees a clear message, download-file fallback works, retry later works.
- Double-click Submit / replayed `collect_id`: exactly one issue is created.
- Huge proxy log / DB: bundle truncates oldest-first at the cap and says so in the text.

### Task 2: Scrubber

**Files:** Create `app/ticket_scrub.py`; test `tests/test_ticket_scrub.py`.

**Interfaces:**
- Produces: `class Scrubber` with `__init__(self, secrets: dict[str, list[str]])` where keys are kinds (`"token"`, `"api_key"`, `"password"`, `"provider"`, `"host"`, `"account"`, `"ip"`, `"email"`) and values the exact strings to remove; `scrub(self, text: str) -> str`; `counts(self) -> dict[str, int]` (placeholders substituted per kind, for the "N placeholders substituted" line); numbering is stable per distinct value (`<IP-1>`, `<IP-2>`, `<PROVIDER-1>`, ...; tokens/keys/passwords are `<TOKEN>`, `<API-KEY>`, `<PASSWORD>`, emails `<EMAIL>`).
- Layers, applied in order: (a) exact values longest-first, also matching their URL-encoded and JSON-escaped forms; (b) regex: IPv4, IPv6, JWTs (`eyJ...\..*\..*`), `(token|api_key|apikey|X-Plex-Token|password)=value` and `"key": "value"` forms, `scheme://user:pass@`, emails, any long (>= 32 chars) hex/base64-looking run, hostnames that are not `localhost`/Docker-internal single words (replaced as `<HOST-n>`). Loopback `127.0.0.1` and `0.0.0.0` stay readable.

**Interfaces:**
- Consumes: `ticket_collect.collect_report`, `ticket_scrub.Scrubber`, `ticket_seal.seal`.
- Produces: `async tickets.start_collect() -> dict` returning `{"collect_id": str, "text": str, "counts": dict}` (text already scrubbed; held in a module dict with 30 min expiry, max 5 entries); `async tickets.submit(collect_id: str, note: str) -> dict` returning `{"id": int, "number": int | None, "status": "sent" | "unsent", "error": str | None}`: scrubs the note with the same Scrubber state, builds `text = "VOD Plex Bridge ticket\nTester's note: <note>\n\n" + report`, gzips and seals, inserts a `tickets` row first (status `unsent`), posts, then updates `number`/`status`; `async tickets.list_tickets() -> list[dict]` (no blob, newest first, `ref` = `"VPB-n"` or `"unsent"`); `async tickets.retry(id: int) -> dict`; `tickets.blob_for_download(id) -> str`; `_post_issue(title: str, body: str) -> int` and `_post_comment(number: int, body: str) -> None` via httpx with header `Authorization: token <TICKET_GITEA_TOKEN>`, issue title `VPB <date> <version> - <first 40 chars of note or "Report">`; chunking: split the blob into <= 60,000 char pieces, first = issue body, rest = comments in order.
